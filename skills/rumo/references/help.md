# help — the case map

`/rumo help`, or `/rumo` typed bare with nothing to route: print this table as the answer, don't guess a mode.

| Situation | Mode | Who / destination |
|---|---|---|
| Vague idea, nothing built yet | `align` | conversation; `rumo:scout` for code facts, `rumo:extractor` for logs/transcripts |
| Idea sharpened, ready to become tracked work | `ticket` | publishes a T1 |
| T1 or a plan, any mix of criteria | `build` | `build-size.sh <issue.json>` picks the lane (build §1) → planner (scout facts in its brief, plan ≤ ~20k chars; deps, baseline typecheck and dev server start while it runs) → builders by step `Model` → `accept-wave.sh` once per wave → full suite in the background beside the tiered review → PR → merge on `dev` → worktree cleaned |
| `SIZE fast` or `SIZE visual` from `build-size.sh` | `build` | fast path (build §1): no planner |
| The plan left a seam or an open question | same `build` | the planner's default is taken and written under `## Assumptions`, copied into the PR body (build §4); nobody is asked |
| A step pushes, merges, deploys, deletes files, runs a command built from input, or a hook must see it | same `build` | planner marks it `Risk: security` → opus builder; its Test first lists abuse cases (`hook:`, `third-party input:`, `check-to-use:`, `deletion:`) before `happy:`, written red first; `plan-check.sh` fails the plan when Does names the literal command or Files touch a hook dir/config (a floor, not the rule) |
| The build needs production, data deletion, money, a third party, a real secret, or a value that would have to be invented | same `build` | a Critical question (build §4): asked once with the default and its cost, card `BLOCKED: question`, Relatório `waiting` |
| Stamp on HEAD, suite and checks green | same `build` | push → PR → Follow-up issue → base-merge sequence → `gh pr merge` on `dev` → worktree, branch and plan copy removed (build §8); a release into `main`/`master`, a deploy and a production DB write stay the owner's |
| A typed agent died on a usage limit (Opus quota) | same `build` | re-dispatch at once (build §5 Model limit): builder/planner/judge → `general-purpose` + `model: "opus"`, reviewer → `rumo:reviewer-sonnet`; a wave lane stopped on an API error gets one `continue` before a relaunch (wave §6) |
| "What is waiting on me?" — sessions parked on a question, a `waiting`/`blocked`/`failed` Relatório or an API error | conversation | `python3 -I <rumo>/skills/rumo/scripts/inbox.py [--days N]`: one row per session, oldest first |
| `SIZE small` from `build-size.sh` | `build` | planner with `SIZE: small` (≤ 2 steps, ≤ 8000 chars, `plan-check.sh --small`); a plan that truly needs more leaves as `NOT SMALL` (build §3.3) → builders by step `Model` → tiered review |
| Idea already ready by align's checks, no ticket | `build <text>` | ticketless build (build §1) |
| Trivial one-file change, no ticket | `build` | inline; the reading taken goes into the PR body |
| Any visual/UI change or judgment step, however small | `build` / conversation | main session only — never a builder |
| Visual step ready for the judge | same `build` | `visual-lint.sh --scheme both --shots <dir> <url>` lints (touch, scroll, sticky, native controls, clipped text, contrast) and saves the judge's shots; then the self-check file, one line per brief rule; then a judge — a fresh one after every FAIL, three FAILs → PR with **Visual — not passed**, no merge (build §2) |
| User complains about a visual the build just delivered | same `build` | a fix in this build: rule into `.rumo/visual-brief.md`, fix, re-judge (build §2); `ticket` only for new scope |
| Greenfield or huge feature, way not visible yet | `map` | decision tickets, hands off to `ticket` |
| Asked for `audit` or `triage` (aposentados 2026-10, #12) | `ticket` · `review` | a finding becomes a T1 via `/rumo ticket`; a standalone review runs the `review` skill |
| Security review of a diff, or a build on the sensitive tier | `review` | the sensitive tier adds the `security` axis on `rumo:reviewer`, and the review stamp requires it; built-in `/security-review` only when called standalone |
| Review refused the stamp: Open finding (blocker/major left open) | same `build` / `review` | fix steps → `AXIS: fix` reviewer writes `RESOLVED`/`WITHDRAWN <axis>#<n>` → same `--tier` stamp; only the user's `#waive <axis>#<n>` leaves a finding unfixed; rounds go on without asking while each closes a finding, four at most; an unattended lane ends `BLOCKED: open finding <ids>` |
| Review came back with minors and questions only | same `build` / `review` | stamp now; no fix round — fixed inline under 30 lines (`--fix --inline-fix`, any tier when no §0-scan path is touched) or sent to the Follow-up issue |
| A design question needs running code to settle | `handoff` | out → `prototype` → `handoff` back |
| Something's broken and resists a first glance | `build` | invokes `diagnosing-bugs` inline |
| Mid-build, switching harness/directory/colleague | `handoff` | portable continuation doc |
| Multi-session build needing tracer-bullet split | `ticket` | several linked T1s, then `build` per ticket |
| Several ready T1s / an epic's unchecked issues to build side by side, or one issue to run on a remote host (e.g. `mini`) | `wave` | one Orca session per issue running `build`, each lane on `local` or a remote host such as `mini` (host column in the table, the typed command is the go; `scripts/wave-host.sh` preflights the host; a `FAIL` only on version/hooks → update this machine, `sync-host.sh --apply` and one retry, any other failure falls back to local); caps local 3 / remote 2 as ceilings, and a lane launches only on `fit>=1` (`wave-status.sh` sizes it from free RAM, the kernel's `vm` level and the largest live lane's `mem`); `scripts/wave-lane-prep.sh` turns the lane's LSP plugins off before launch; a wave with a local lane holds `caffeinate -i -w` on the orchestrator's PID; each ~10 min wake-up runs `scripts/wave-status.sh <name>` once (every slot (issue `#N` or issueless `lane:<slug>`) with `idle`/`stalled`/`mem` + each host's load/RAM/`vm`/`fit` + local `awake`), and `stalled=yes` goes to wave.md §6 like a dead session; `pressure=yes` pauses on low memory or `vm=critical` always, on load only when `ps` shows the wave's processes carrying it (wave.md §5); a lane still `PAUSADO` the wake-up after a `CONTINUE` gets it once more |
| PR opened with minors, questions or Waivers left open | `build` §8 / `wave` lane | one Follow-up issue `Follow-up #<PR>: <PR title>`, linked both ways (`Follow-up: #<issue>` in the PR body, no `Closes`); nothing open → no issue; an unattended lane hands its text with the PR body |
| Lane or Worker launched with a host-written Mandato | `build` / `wave` lane | `mandato.py check <wt>` before shipping (build §8): valid → its alcance (`pr` stops before merge, `merge` goes on); refused → ship nothing, `BLOCKED: mandato <reason>`; absent → `AUTHORIZED:` as before; every build ends with a `RELATÓRIO:` line before `NEXT:` |
| PR ready to merge, base moved since the review | `build` §8 / `wave` lane | `git merge origin/<base>` → bump → suite + typecheck → `review-stamp.sh --base-merge` → push → `gh pr merge` (wave.md §Merging) |
| Delegating outside a build: a precise build brief · bulk logs/JSON · web collection · a code lookup | conversation | `rumo:builder` (WORKTREE · TASK · FILES · VERIFY) · `rumo:extractor` · `rumo:collector` · `rumo:scout` — untyped opus only for research, diagnosis, judgment |
| Mistakes repeating, want the setup to learn from them | `/learn` (separate command) | lessons ledger → promotion diffs you approve |
| Where a build's clock time went: critical path, phases, stalls, owner touches per build | `/learn review` (separate command) | its report prints the `learn.py phases --days 14` block; wave orchestrators and launcher messages are counted apart from builds and from the owner |
| Typed `/rumo` bare, no repo task in mind | *(this)* | this case map, no mode fires |
